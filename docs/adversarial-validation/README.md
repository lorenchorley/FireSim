# Adversarial validation

Documents for the adversarial-review process (`.claude/skills/adversarial-review/`) and the work to extend it.

## Versioning

Each iteration is a new file. A committed file is not edited afterwards. The first version keeps the plain name, and later versions add a suffix: `NAME.md`, `NAME-v2.md`, `NAME-v3.md`. A revision's status line says which ruling items it applies, and its last section lists what changed and what was left open. A review run is stored under `reviews/run-N/` as the pack, the five reviewer reports and the judge's ruling.

## Files

| File | What it is | Revision |
|---|---|---|
| `MISSION.md` | Mission statement: goal, principles, use cases UC0 to UC4, research need, open questions | 1 |
| `ASSESSMENT-2026-11-12.md` | First answers to the open questions Q1 to Q4 | 1 (unchanged) |
| `ASSESSMENT-2026-11-12-v2.md` | The assessment with ruling items M1, M2 and S1 to S3 applied | 2 |
| `reviews/run-1/` | Adversarial review of assessment revision 1, against `MISSION.md` | |

## Notes on `reviews/run-1/`

The files are the run's output as it was produced. `pack.md` and the reports name session paths that no longer exist, and the line numbers in the reports refer to `ASSESSMENT-2026-11-12.md` (revision 1), which is unchanged. The judge's ruling and the reports are model output.
