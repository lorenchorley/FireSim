## 2. Data model and units

**"The wind the fire feels" = `env.windU/V`**, m/s east and north on the fire grid (30 m, or 20 m up to 6 km): the wind the spread model is given at each cell, a 10 m open-ground equivalent. 3-D tiers: the resolved air sampled at `z_ref = max(50 m, canopy + 20 m)` above ground (`atmosphere/params.ts:214-215`), scaled by the complex kappa, plus the fire's own indraft inside about two plume heights (`fireWindTier`, `atmosphere.ts:952-1012`, head correction), plus the sub-grid slope-flow top-up (cap 3 m/s, full along the fall line at night), plus the lee-eddy blend (`base.ts:727-776`). Fast tier: the diagnosed wind with the same top-ups and the pyrogenic indraft, refitted every 60 s. It is finer than the 100-270 m air but not a resolved 30 m flow, and near a fire it converges on the fire: true to what drives the fire, and said so.

**`FireWindRaster`** (`core/types.ts`, additive): `grid: GridSpec` (block centres: `cellSize = k x cs`, `x0' = x0 + (k-1)/2 x cs`, same for y, `nx' = ceil(nx/k)`; edge blocks average the cells they have), `u, v: Int16Array` (`round(mean x 100)`, clamp +-32767, a non-finite mean is 0), `block: k`, `time: s`. `k = max(1, round(60 / cs))`: 2 at 30 m, 3 at 20 m, 2 at 25 and 40 m. Error: at most half a quantum, **0.005 m/s** (MEASURED: max 0.00500 over 3 km to 12 km). Decode `q x 0.01` into Float32 (no scale table, unlike `airPack.ts`: a fixed quantum covers 327 m/s).

Per picture (u + v + 64 B fixed; the fire grid is extent / cell):

| Area | Fire grid | k | E2 grid | Bytes | Keyframe today (model) | E2 share |
|---|---|---|---|---|---|---|
| 3 km, 30 m | 100 x 100 | 2 | 50 x 50 | 10,064 | 571,136 (3-D, 900 columns) | 1.8 % |
| 6 km, 30 m | 200 x 200 | 2 | 100 x 100 | 40,064 | 1,634,636 (2,025 columns) | 2.5 % |
| 6 km, 20 m | 300 x 300 | 3 | 100 x 100 | 40,064 | 2,634,636 | 1.5 % |
| **12 km, 30 m (largest)** | 400 x 400 | 2 | 200 x 200 | **160,064** | 4,034,636 standard, 4,971,536 high (3,600 columns, 24 levels), 3,224,636 + 243 kB wind list on fast | 4.0 %, 3.2 %, 4.6 % |

Keyframe model = `256 + 20 x cells + columns x (12 + nz x 20) + 4 nz` (`memoryModel.ts:116-119`), columns from `atmosphereGrid` (`clamp(extent/45, 100, 270)` m; standard 45 columns a side at 12 km, high 60). In the history (a keyframe every 300 s): **6 h = 73 keyframes: 0.70 MiB (3 km), 2.79 MiB (6 km), 11.1 MiB (12 km); 12 h = 145: 1.4, 5.5, 22.1 MiB** nominal, before thinning. Not a new budget: the store holds to its 48-160 MiB by thinning older keyframes, so E2 costs 1.5 to 4.6 % of the keyframes it can hold (at 12 km the history is already over budget without E2: 73 x 4.03 MB = 294 MB against 160 MiB). Newest snapshot +0.01 to 0.16 MB. Wire: +0.01 to 0.16 MB a message (transferred, `host.ts`). **The three picture tiers (Low/Medium/High render quality) change nothing here**: the data depends on extent and cell only; the engine tier changes only how often the values change (section 0.9). Publish cost MEASURED (block mean + quantise, node, shared machine): 0.08 ms (3 km), 0.39 (6 km, 30 m), 0.49 (6 km, 20 m), **1.66 (12 km)**; phone [est] x2.35 (plan 6.2: 41.1 / 17.5 ms) = 3.9 ms a snapshot at 12 km, about 2.3 % of a core at 6 snapshots a second (3.9 ms x 6 = 23 ms a second). Decode into Float32 MEASURED 0.004 to 0.071 ms.

**Where it is read:** the glyph layer decodes it into two alternating Float32 stores made on first use of `'felt'` (80 kB each at 6 km, 320 kB at 12 km; the builder reads one while the next snapshot fills the other, as `HeightRaster` does); the map reads it through the overlay field. History: `Keyframe.fireWind`, `compose()` returns `key ? key.fireWind : head?.fireWind`, so a scrubbed picture shows the keyframe's wind (up to 300 s old), stamped by `fireWind.time` ("air from 14:05"). Truncation and thinning drop it with its keyframe. Calm nights: speeds under 0.3 m/s are the glyph engine's calm dots; at night the slope-flow top-up means the field is a downhill drainage pattern (up to 3 m/s) where the 10 m open-ground wind is near zero. **That sentence is a claim to check on the `calm-night-katabatic` preset on both tiers (V6) before the words ship.**

E1b units: km/h, `Float32` `nx x ny` on the raster's own grid (atmosphere grid for `'fire'` and numeric heights, 60 m grid for `'felt'`); NO_DATA outside the raster.

## 5. The speed test button

**What it is.** "Speed test", plan 5.3 line 188 / 0.3.1 row 729 / 17.4 line 1006, never built. Frozen kernels, run for about 2 s off the main thread, shown against a fixed reference; for comparing phones before any run; the engine's own measured step is the better number once a run exists.
**Where.** Debug statistics screen, group "What this phone can do" (reachable from Setup before any run: "the phone groups are live", plan 5.1). Under the three sentence rows: row "Speed test" (text) and a `button` (`speed-test`, standard size, 44 px) with a polite status line (`speed-test-status`, `aria-live="polite"`, never `role=alert`, no toast, no pop-up). The text export (`debugStatsToText`) includes the row.
**Words.** Idle: "Not run yet. Takes about 2 seconds." Button "Run the speed test". Running: "Testing, about 2 seconds." (button disabled, `aria-busy`). Result: "Air kernel 25.1 million cell updates a second, memory copy 3.8 GB a second. About 3.2 times slower than the build machine. Test version 1, 14:05. One short test on one thread: heat and other apps change it, so run it twice. It does not predict a run; the simulation's own measured speed is the better number once one exists." (numbers illustrative). Disabled with the reason in the status line: while a run plays or the engine is computing ("Pause first so the test is fair"), while the app is hidden, or when `Worker` is missing and the main-thread fallback is refused ("This phone cannot run the test here"). Closing the screen mid-test terminates the worker and shows nothing.
**How.** `src/ui/speedTest.ts` (pure, node-tested): K1 "air stencil", a fixed 45 x 45 x 20 Float32 grid (the standard tier's size, 40,500 cells) with a 7-point stencil and trilinear gathers per cell, inputs from a fixed LCG seed (never `Math.random`); K2 "memory copy", a 16 MiB Float32 copy loop. Each is warmed 0.2 s then timed 0.8 s by completed sweeps; score = work / elapsed. **Frozen:** `SPEED_TEST_VERSION = 1`, and a unit test pins the checksum of K1 after 3 sweeps and of K2 after 2 on fixed inputs (any edit to a kernel fails it and forces a version bump). Reference `SPEED_TEST_REFERENCE` = the same code measured by `SPEEDTEST_REF=1 npx vitest run src/ui/speedTest.reference.test.ts` on the build machine (node 22), pasted with its date; the result shows the ratio of each kernel and says "the build machine" (no CI runs the repo; plan's "in CI" means this). `src/ui/speedTest.worker.ts` is the worker entry (`new Worker(new URL('./speedTest.worker.ts', import.meta.url), { type: 'module' })`, the form `client.ts:198` already uses, so it works in the APK); if constructing it throws, the same sweeps run on the main thread in slices of 8 ms (the in-thread engine uses 40 ms chunks, `SIM_PARAMS.chunkMs`, which would show as jank in a test the user is watching), so a phone on the in-thread engine is not left without a test.
**Determinism (plan 4 rules 1 and 2).** The test has no input from the scenario, the engine or the clock beyond `performance.now()` for its own timing; it writes nothing the engine reads; its result is not read by Auto, the tier choice, the pace tracker or any worker message. A dependency test fails if anything under `src/sim`, `src/atmosphere`, `src/fire`, `src/embers`, `src/explain` imports `speedTest`; an e2e compares snapshot hashes of a run paused and tested against one not tested.
**Not built:** H-sim (BLOCKED, D17/S6).
